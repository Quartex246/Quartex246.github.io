前言

其实我感觉这种文章应该烂大街了，但是我突然想到欸我还有个博客哦，刚好这个月的素材还没有写，那就赶紧写上吧

为什么要写？主要是因为Microsoft Todo（后文简称MSTD），这个我一直在用但是却不常用的清单软件宣布要停止服务了。考虑到我还有一堆形式主义的事情要搞，所以我需要找一个新的待办清单软件

现如今AI肯定是有能力来复现一款像MSTD那样的清爽又直观的软件的，而且如果经济条件允许，你甚至可以复刻全平台版本。但最大的问题在于这种自制版多设备同步不是特别方便，所以我去找有没有现成的开源方案，最后暂时先选择了Super Productivity（后文简称SP）

SP的功能很丰富，而且整体界面和MSTD差不多清爽，唯一的问题是他自己的同步服务SuperSync的验证邮箱不知为何迟迟无法发到我的邮箱中，所以为了继续浪费我的时间，我决定尝试自己搭一个小的服务器来同步

用来作为服务器载体的小主机是一个闲置的电脑棒。高中时我朋友用这个东西加一对作为赠品的联想键鼠打通了《蔚蓝》。机器只有2+32GB的存储搭配，用的是英特尔Z3735F。接口也十分简洁——只有有一个标准A口，一个供电MicroUSB，数据传输MicroUSB和一个TF卡口

这款机器的处理器是最奇异搞笑的。理论上它支持64位的系统，但他却用着32位的引导。这意味着有相当一部分现代系统甚至无法被正常引导，除非在镜像中加入对应的引导文件。

即使加入了引导文件成功安装，也不一定说明能支持系统正常使用。这既可能是架构的问题，也可能是性能的问题。FydeOS轻量版不支持打开安卓虚拟机，浏览器但凡多打开两个标签页就会开始卡。Windows最多只支持32位8.1，但凡升个级就能卡的无法使用。我原先想把它作为一个小的电视盒子，结果Android X86只能在安装时被引导，之后就会跳转到GRUB。Android TV呢？他不支持5Ghz的WIFI，我连安个软件都不行

总之，作为从那个寨板黄金年代过来的U，也许只有安装Windows 8.1才是他最好的归宿吧。

跑题了，反正在被这个设备折磨了良久之后，我决定还是为这个设备刷入Linux，结束折腾他的漫漫长路。

接下来的内容都是让AI写的，不过为了加点人情味，我会根据情况自己加点东西

部署 Nextcloud（Debian 12 + LAMP）

Z3735F 的 32 位 UEFI 引导问题需要在系统安装阶段解决，所以我选择的，或者说AI选择的，是Debian 12. 我试过了，但凡现代点的Linux都无法安装，Debian 13即使加入了32位引导文件也会被引导到GRUB.

如果有条件一定要选择完整的安装镜像，而不是什么网络安装版。这东西我搞了一下午，百分之五十都花在了下载东西上。

在 Nextcloud 中创建“应用密码”

不要用 Nextcloud 主登录密码去配置 Super Productivity。应用密码可以独立撤销、权限受限，也更适合第三方客户端。

  1. 登录 Nextcloud 网页界面，点击右上角头像 → 个人设置 (Personal settings)。
  2. 左侧菜单选择 安全 (Security)。
  3. 滚动到页面底部的 应用密码 (App passwords) 区域。
  4. 输入一个易识别的名称（例如 Super Productivity），点击 创建新的应用密码。
  5. 立即复制生成的密码（格式类似 xxxxx-xxxxx-xxxxx-xxxxx-xxxxx），关闭页面后它不会再完整显示。

配置 Super Productivity 同步（二选一）

Super Productivity 连接 Nextcloud 有两条路径，用途不同，按需选择。

路径 A：文件同步（同步全部数据，推荐日常使用）

这种方式通过 Nextcloud 的 WebDAV 文件接口，同步 Super Productivity 的完整数据（任务、项目、时间追踪、设置等），适合在多台设备间无缝接续。

  1. 打开 Super Productivity，进入 设置 (Settings) → 同步与备份 (Sync & Backup)。
  2. 同步提供商选择 Nextcloud。
  3. 填写：
    • Server URL：你的 Nextcloud 地址，例如 http://小主机IP 或 https://你的域名。
    • Username：Nextcloud 用户名。
    • App Password：第二步生成的应用密码。
  4. Sync Folder Path 可以留空，应用会自动使用默认路径；如果希望指定文件夹，填写的是 相对于 WebDAV 根目录的路径，例如 /super-productivity，而不是服务器上的绝对路径。
  5. 按需设置同步间隔，或勾选“仅手动同步”。保存后即可生效。

一个 CORS 提醒：如果你使用的是 Super Productivity 的网页版（而不是桌面客户端），Nextcloud 默认可能拦截来自 https://app.super-productivity.com 的跨域请求。桌面版和 Android 客户端通常不受此限制。如果确实需要网页版同步，可以在 Nextcloud 中安装 webapppassword 应用，并将上述地址加入白名单。

路径 B：CalDAV Todo 同步（与 Nextcloud“任务”应用互通）

如果你希望 Super Productivity 中的待办事项能出现在 Nextcloud 自带的任务 (Tasks) 应用中，或者在手机原生任务应用中查看，就使用 CalDAV。它同步的是标准的 VTODO 格式，不是全量数据，时间追踪记录等不会出现在 Nextcloud 侧。

  1. 在 Super Productivity 中打开 问题提供器面板 (Issue Provider panel)，点击 “+” → 选择 CalDAV Todo。
  2. CalDAV URL：填写账户级基地址，而不是某个日历的地址：
  3. 日历名称 (Calendar Name)：填写 Nextcloud “任务”应用中你要同步的那个列表名称。匹配是精确的，包括大小写和空格。如果显示名称匹配不上，应用会尝试用日历 URL 的最后一段作为名称。
  4. 用户名和密码：用户名填 Nextcloud 用户名，密码填应用密码。
  5. 点击 测试连接，确认成功。
  6. 在 高级配置 (Advanced Config) 中，选择一个 默认项目 (Default Super Productivity Project)，并确保 “自动导入到默认项目” 处于勾选状态。这一步不能省：如果不选项目，任务只会出现在集成面板的列表里，不会自动进入你的项目视图。

Z3735F (2GB) 必须做的关键优化

以下三件事直接决定 Nextcloud 在你的设备上是否“能用”，建议在部署完成后立即处理。

① 启用 ZRAM（优先级最高）
ZRAM 在内存中创建压缩交换空间，对 2GB 设备的效果远好于传统 swap 分区，能显著降低因内存不足导致服务崩溃的概率，同时减少对 32GB eMMC 的读写磨损。

Nextcloud 默认的 PHP memory_limit 可能设置得较高，在 2GB 总内存下必须收紧，防止单个 PHP 进程吃掉过多资源。编辑对应的 php.ini（Apache 模式下通常是 /etc/php/8.2/apache2/php.ini）：
